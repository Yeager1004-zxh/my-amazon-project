# V1.0 开发范围与验收计划

## 产品边界

V1.0 只交付“新品推广周报自动生成”：从领星 OpenAPI、领星 MCP 或用户导出的 Excel/CSV 获取真实数据，按店铺、SKU 和日期核验并标准化，计算新品推广周报指标，再写入原 Excel 模板并输出诊断日志。

广告管理、库存管理、利润管理和定时运营自动化不属于 V1.0。后续模块可复用已验证的数据提供层，但当前不为它们增加页面、数据表或业务逻辑。

## 当前代码审查结果

- MCP 客户端已实现连接、会话、目录搜索、业务 Schema 读取和只读许可；`action.params` 的业务字段校验已在 `main` 修复并有自动回归测试。GUI 目前仍要求用户手工输入 search/业务参数，并选择业务 Tool ID。
- Excel/CSV 导入、显式字段映射、日期/数值解析、D01 时间线、广告花费异常检查、模板样式延展和 JSONL 校验日志已经存在。
- OpenAPI 目前只实现 Token 获取。店铺列表、销售查询和广告查询仍 fail-closed；不得把未核验的接口结果写入周报。
- 数据来源读取、标准化、归属与重复检查、指标聚合及 Excel 写入目前主要集中在 `report_generation.py`。提供者协议 `providers/base.py` 尚未连接 MCP/OpenAPI 与报表管线，缺少稳定、可独立测试的 V1 日级数据契约。
- 当前自动化测试使用本地测试夹具；ex3106 真实销量和广告活动实际花费，以及 Windows 10/11 打包运行均未完成验收。

## 剩余任务、顺序与验收

| 优先级 | 工作项 | 依赖 | 验收标准 |
|---|---|---|---|
| P0 回归门槛 | MCP action 外层和业务参数 Schema 分开验证 | 已有 search 返回 Schema | 外层只接受 Schema 定义的 tool ID 与 object params；params 字段按当次 search 的业务 Schema 验证。非法 ID、缺失/多余字段、错误类型或 Schema 变化均不发送 action；测试覆盖空的通用 params Schema。 |
| P1 数据契约 | 建立适用于本周报的最小标准化日数据结构，并将 Excel/MCP/OpenAPI 输出接入同一校验和计算入口 | P0；现有 `source_reader.py` 与报表汇总规则 | 记录明确包含店铺、SKU、日期、可用指标及来源/覆盖信息；空值与明确零值可区分；每条规范化记录可通过单元测试验证。只抽取 V1 所需字段，不建设通用工作流引擎。 |
| P2 销售读取 | 按 EX 店铺和 ex3106 建立固定、只读查询流程，确认每日销量、销售额、首单日期和覆盖日期 | P1；Windows MCP 授权、实际 search Schema 与查询权限 | 按日期及汇总分别与领星原始销售报表核对一致；D01 为首个正销量日；日期缺口保持空白；店铺/SKU 不唯一匹配时停止对应字段并输出诊断。 |
| P3 广告实际花费 | 核验广告查询工具、字段含义及活动到 SKU 的归属粒度，接入实际花费 | P1/P2；领星官方字段说明和 Windows 真实数据 | 对 EX/ex3106 核对 2026-08-04、08-05、08-06 以及区间总额；与实际花费原报表一致；共享活动花费不会重复归属；归属不明确或数据缺失时留空并报告异常。 |
| P4 查询到报表 | 将已核验的规范化数据送入现有周报生成器，统一处理 API 与文件来源 | P2/P3；原模板和既有模板测试 | 真实查询可生成新 Excel 和校验日志；模板格式、周次、合并单元格及 D61+ 连续日期正确；日目标销量、发货时间、推广阶段不被覆盖；无来源值不被写成 0。 |
| P5 日常 GUI | 将已验证查询流程包装为店铺选择、SKU/日期输入和一键生成，不再暴露 JSON、Tool ID 或 Schema 输入 | P4；稳定且可识别的查询配方 | 在 Windows 完成店铺选择、多 SKU 查询、进度和失败原因展示；工具/Schema 未核验或发生变化时安全停止；用户普通操作无需手写参数。 |
| P6 Windows 发布 | Windows 10/11 安装验收、PyInstaller 打包与交付说明 | P5；Windows 目标机和本地凭证 | 在用户 Windows 电脑使用本机凭证完成连接、真实数据比对和 Excel 导出；安装脚本、启动脚本、EXE 打包步骤可复现；凭证不进入仓库、配置文件或日志。 |

## 模块依赖

```text
GUI
 └─ 应用流程：选择店铺/SKU/日期 → 选择已核验数据配方 → 展示进度和诊断
     ├─ 数据提供者：MCP / OpenAPI / Excel-CSV
     ├─ V1 标准化与校验：店铺、SKU、日期、销量、销售额、活动实际花费、来源覆盖
     ├─ 周报计算：D01、自然日序列、每日与周度指标、缺失值和异常
     └─ Excel 输出：原模板、D61+ 样式、人工字段保护、校验日志

凭证与本机配置 → MCP/OpenAPI 提供者
日志与测试     → 覆盖每个边界及端到端 Windows 验收
```

这只是 V1 的职责边界，不要求提前实现通用插件系统。现有 MCP action 参数校验、Excel/CSV 读取、周报计算和模板写入分别按一个可独立验证的改动推进，每次改动后运行对应自动测试；真实凭证测试只在用户 Windows 本机完成。

## 发布门槛

云端模拟传输和合成夹具测试只能证明程序逻辑，不代表领星真实业务验证。V1.0 在以下事项全部完成前不得标记为正式验收：ex3106 销售数据比对、2026-08-05 前后广告活动实际花费核验、真实数据生成工作簿逐项检查，以及 Windows 10/11 本机运行和打包测试。任何未验证字段都应留空并在诊断中说明。
