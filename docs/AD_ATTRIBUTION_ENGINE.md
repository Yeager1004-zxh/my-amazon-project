# SP / HSA / SD 广告实际花费归属

V1.0 按 SKU、站点报表日期读取并核验实际花费。HSA 是领星品牌广告费用来源，普通 Sponsored Brands 和视频广告不再作为 SKU 归属前提。活动名、广告归因销售额和猜测比例都不用于商品归属。

## 数据与核对

1. 查询所选 SID 对应的本地 SKU → MSKU/ASIN 映射。SP 和 SD 使用日期报表内的商品标识；HSA 使用活动、广告组和创意标识。
2. 按 `sid + profile_id + campaign_id + report_date` 识别活动，并用 `ad_group_id` 限定 HSA 费用行。商品级行另使用 `ad_id`、MSKU、ASIN 做精确匹配。
3. SP 商品行和 SD 商品行各自与活动总额核对。HSA 广告组成本之和与活动成本核对。活动总额只作核对基准，绝不与商品行或广告组行再次相加。
4. 重复行、SID/Profile/Campaign/日期不符、冲突的 MSKU/ASIN、活动和明细金额差异都会阻止相关记录归属。缺失记录不作为零花费；只有完整报表中明确存在的零成本记录才表示零。
5. 只有 SP、HSA、SD 覆盖相同日期、所有费用归属完整、币种与日期口径通过验证时，才把三类费用合计写入模板。任一部分失败或未归属时，总广告花费和 ACOS 保持空白。

金额全程使用 `Decimal`，不将活动花费重复计入多个 SKU。

## HSA 广告组自动归属与异常兜底

HSA 活动报表和广告组报表按 `profile_id + campaign_id + report_date` 返回活动 `cost`，并按 `ad_group_id` 返回同日组级 `cost`。活动级总额只用来核对组级金额之和，不会再次计入 SKU。

`hsaProductAds` 提供当前目录中的 `profile_id`、`campaign_id`、`ad_group_id`、`ad_creative_id` 和 `asin[]`，可与本地 SKU→ASIN 映射交叉，自动找出唯一 SKU 候选。文档同时列出 `creation_date`、`last_updated_date`，但没有说明这些时间代表推广商品关系的有效期，也没有提供报告日版本或关系变更历史。HSA 报表的日期记录没有 ASIN/MSKU/Creative ID。因此当前公开 Schema 组合能自动找候选，不能证明历史报表日的推广关系。代码只有在提供完整、且来源明确保证对应该报表日的历史商品证据时，才会把 `identity_valid_for_report` 置为真并自动归属；目前 OpenAPI 适配器不会把当前目录或快照提升为这类证据。

当前目录查询成功后，程序按观察时间把非空创意关系快照保存在当前 Windows 用户的 `%APPDATA%\MyAmazonProject\hsa_ad_group_mappings.json`。快照只存 SID、Profile/Campaign/Ad Group/Creative ID、顶层 ASIN、状态和观察时间，不存名称、金额、API 请求或凭证。每次快照只是该时刻观察到的关系；两个快照之间即使没有观测到变化，也不能证明关系一直连续，更不会自动生成历史有效期。

只有无法由历史证据自动确认的唯一候选才进入异常兜底。点击“批量核验 HSA SKU 候选…”，一次查看多个候选组、关联 ID、ASIN 和查询中出现日期；可批量选择并为所选组录入经核验的共同有效日期范围。再次明确确认后，程序原子写入 SID、Profile ID、Campaign ID、Ad Group ID、本地 SKU 和首尾有效日期。本地确认只在完整 ID 与报表日期匹配且活动/广告组核平时复用；映射冲突、组内多 SKU、候选不唯一或不完整时仍保持未归属。不同有效期应分批保存。确认内容不含凭证，不进入 GitHub。

预览状态汇总自动归属组日数量及金额、本地确认组日数量及金额、唯一候选组数量、已核明未归属金额，以及金额未知的日期数。已知验收结果只用于 Windows 本地对照，不写入代码或映射规则。不能仅凭费用金额、活动名称或快照间隔自动匹配。

`sbDivideAsinReports` 的字段结构仍有疑问，因此客户端继续在发请求前阻止该接口；它不再是单 SKU 专属 HSA 活动归属的前置依赖。

## 进入 Excel 的门槛

广告预览会展示 SP、HSA、SD 单项归属、未归属金额和活动/明细核对状态，但不会仅因个别 SKU 已匹配就把部分和写进模板。正式总额要求同一店铺和日期的 SP/HSA/SD 报表都已成功、逐活动核平、HSA 广告组无未归属项，且币种及日期口径已验证。GUI 当前仍将币种/日期验证标记为未通过，因此 OpenAPI 生成的广告总额暂留空；销售周报仍可正常生成并在校验日志说明原因。

## Windows 只读验证

1. 更新到开发分支最新提交，打开软件并刷新授权店铺。
2. 选择店铺、输入测试 SKU 与单日站点日期，点击“查询 SP / HSA 品牌广告 / SD 花费并预览”。
3. 分别检查 SP、HSA、SD 活动和明细记录数、逐活动成本差异、HSA 广告组未归属金额及完整性状态。核对时使用领星相同店铺、同一报表日期和币种。
4. 对于目录只提供候选的广告组，打开批量核验窗口，一次选择需要确认的候选，填入运营人员实际核验过的共同有效范围并确认；重新查询后，匹配范围内组费应只计一次。不要把目录观察日期或查询范围当作关系有效期。
5. 只有后台核对通过后，才可提供脱敏的“本地归属正确/不正确、活动与组成本是否核平、报表日是否相同、币种是否相同”反馈。不要发送凭证、Token、原始响应或真实业务明细。

云端合成测试不代表真实 API 验收。SP 和部分 SD 的 Windows 实测由用户报告；新 HSA 日期归属流程尚需 Windows 实测。真实店铺、SKU、金额和原始记录不保存在仓库。
