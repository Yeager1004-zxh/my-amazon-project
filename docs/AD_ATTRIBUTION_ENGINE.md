# V1.0 SP+SD 广告实际花费统计

正式统计范围为 `SP_SD_ONLY_CONFIRMED`。软件按所选店铺 SID、本地 SKU 和站点报表日期，自动获取 SP 与 SD 商品级实际花费，分别核对活动总额后再汇总。普通 SB 与 SBV 不属于 V1.0，也不作为完整性门槛。

## 查询与归属规则

1. 用所选店铺和本地 SKU 获取动态 MSKU/ASIN 映射；不硬编码店铺或 SKU。
2. 每个站点日期分别读取 SP Campaign/ Product Ad Reports 与 SD Campaign/Product Ad Reports。正常路径不读取 HSA 报表，也不读取当前 SD `sdProductAds` 目录。
3. 活动和商品行使用 SID、Profile ID、Campaign ID、报告日期核对；商品行通过报表内 MSKU、ASIN、Ad ID 映射到本地 SKU。无法唯一归属或 MSKU/ASIN 冲突的行不计入目标 SKU。
4. SP 商品行总额必须与 SP 活动成本一致；SD 商品行总额必须与 SD 活动成本一致。两类各自核平后按同一 SKU、站点日期相加。活动成本只作校验，不与商品明细重复累计。
5. 同一日期的 SP 或 SD 请求缺失/失败、分页不完整、活动/商品金额不一致、身份冲突或币种未确认时，该日期周报广告花费保持空白。只有两类均完整且归属可验证时，才将完整商品报表中无匹配商品记录视为零；接口空响应或缺失报表不视为零。
6. API 金额使用 `Decimal` 汇总。广告 API 没有返回币种字段，生成流程要求同一 SID 每日销售响应提供唯一 `currency_code`，并把同 SID、同站点日期的 SP/SD 报表按该店铺币种对齐。若 Windows 后台对照发现币种或日期不一致，必须保持空白并修正验证规则。

## 预览及 Excel

预览分开展示 SP、SD、未归属花费与完整性状态。预览不额外查询每日销售币种，因此 SP+SD 合计保持空白；正式生成会从同一 SID 的每日销售响应核对唯一币种，满足完整性条件后写入“广告花费（SP+SD）”。失败、缺失、未归属、核平差异和明确零分别提示。SB/SBV 缺失不出现在预览，也不会阻止周报生成；AsinListNew 的 `spend`、`shared_ads_sb_cost`、`shared_ads_sbv_cost` 等未经核验字段不替代 SP+SD 商品实际花费。

周报没有取得同一 SP+SD 类型范围和可比归因窗口的广告销售额时，广告销售额与 ACOS 留空。若以后从离线映射导入 SP+SD 组合广告销售额，只有在其 `coverage_scope` 同为 `SP_SD_ONLY_CONFIRMED` 且每日字段完整时才允许计算 ACOS。销量、售价来自销售查询；自然单不通过总订单数减广告单推算。所有缺失字段保持空白。

更新已有工作簿时，SP+SD 不完整日期会清除旧生成广告花费，避免把过期总额继续当作当前统计范围；日目标销量、发货时间、推广阶段等人工字段仍保留。每次生成旁写校验 JSONL，记录日期级范围和异常，不写密钥或 Access Token。

## 旧 HSA 代码

HSA（SB/SBV）活动、广告组、创意目录、历史候选和本地映射代码保留在仓库，以备以后重新启动相关范围的研究；当前 GUI 正常流程、预览和周报生成不调用它们。V1.0 暂停 SB/SBV 分摊和广告组人工绑定，不将旧 HSA 结果混进 `SP_SD_ONLY_CONFIRMED`。恢复前必须重新确认官方 Schema、历史商品归属与金额口径。

## Windows 验收

1. 更新开发分支，刷新店铺，选择店铺、输入 SKU 和单日站点日期；先运行 SP+SD 只读预览。
2. 检查客户端未发送 HSA/SBV 请求，并确认 SD 历史费用查询没有请求当前目录接口。
3. 分别将 SP、SD 商品级花费与各自活动报表核平，再与领星后台相同店铺/日期/币种对照；核验两类型合计、缺失、查询失败和显式零行为。
4. 使用原始 Excel 模板生成文件，检查“广告花费（SP+SD）”列、销售数据、连续日期/D61+、样式和人工字段保护；更新已有文件时确认不完整广告日期不会保留陈旧花费。
5. 只反馈脱敏的请求/业务状态、字段结构和是否与后台一致，不提交 AppID、AppSecret、Token、店铺/SKU 明细或完整响应。

云端测试使用合成数据，不代表真实领星数据验收。用户报告 SP 及若干日期 SD 商品花费的 Windows 验收通过；本轮 SP+SD 正式写入还需 Windows 端到端核对。
