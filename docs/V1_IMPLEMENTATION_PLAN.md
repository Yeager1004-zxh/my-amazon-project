# 新品推广周报 V1.0 实施清单与验收标准

本计划涵盖 V1.0 正式交付范围。当前开发分支为 `feature/weekly-report-v1`，稳定版 `main` 不在本阶段直接修改。业务范围仅限新品推广周报；广告管理、调价、库存管理、利润分析及企业云平台不属于 V1.0。

## 产品路线与当前验收基线

- **领星 OpenAPI** 是主数据来源；官方 MCP 保留为辅助查询和核验渠道；领星 Excel/CSV 是接口不可用时的备用来源。
- 已有模板生成器支持原模板格式、连续日期、D61+、校验 JSONL、多个 SKU 和增量更新时保留人工字段。
- Windows 本地真实验收：动态店铺列表已通过；用户报告 SKU 映射、每日销量、订单量、销售额查询在 EX-shop-US / ex3106 与领星后台一致。此记录是用户提供的验收结果，Codex 云端没有访问凭证或原始数据。
- 已实现的销售 API 文档范围：产品表现 `POST /bd/productPerformance/openApi/asinList`、每日统计 `POST /erp/sc/data/sales_report/asinDailyLists`。产品表现日期窗口上限 92 天；每日统计按站点自然日查询，按 ASIN/MSKU 和指标类型分页。
- **D01 规则已由用户最终确认：手动输入并确认。** 每个店铺/SKU 独立设置 `YYYY-MM-DD`，按该店铺站点日期解释；本机持久化，后续更新复用。不能从商品创建日期、订单、首个有销量日期或其他来源自动替代。修改已有工作簿起算日之前必须警告日期错位并重新确认。订单列表不再是 V1.0 的 D01 依赖。
- 用户已提供的 AsinDailyLists 文档未说明按日期查询的令牌桶补充速率；收到 429 必须停止，不猜测等待时间、不自动重放。多日历史查询的限流行为需在 Windows 授权环境实测。
- 用户报告 SP 广告实际花费已在 Windows 与领星后台核对一致；此真实验收结果来自用户反馈，云端没有凭证或原始业务响应。
- 最新 Windows 反馈：用户已核实一个 SB SKU 级费用及店铺级费用，但软件仍未能自动归属该历史费用。用户另报告多日 SD 历史商品报表与领星后台一致。历史 SD 商品行提供报表日 SKU、ASIN、ad_id、campaign_id、cost，应直接用于该日映射；当前目录只作补充诊断。云端未读取企业原始数据，仓库不记录具体店铺、SKU、日期或金额。
- 已收到 SP Campaign/Product Ad、SB Campaign/Ad Group、SD Campaign/Product Ad，以及 SB Product Ads、SD Product Ads 的官方 Schema。只读目录接口已接入：SB 顶层 `asin` 通过 profile/campaign/ad-group/creative ID 显示当前候选；SD SKU/ASIN/ad ID 显示当前交叉核验项。`hsaProductAds` 不含报表日期或历史版本，目录快照不会证明历史推广身份。
- **广告归属方向已调整为自动匹配优先。** `ad_attribution.py`：SP/SD 历史商品报表按唯一 MSKU/ASIN 自动映射；SB 当前目录 ASIN 只显示候选，不自动将历史广告组 cost 归入 SKU。只有历史有效推广身份、唯一商品归属、活动与广告组金额核平，或官方 SKU 级分摊语义被核验后才可自动归属。现有 GUI 详情显示 ASIN、Ad ID、广告创意目录和历史有效性状态。
- 当前 `productPerformance` 映射没有逐日 MSKU/ASIN 有效期；缺少历史身份时效证据、广告 cost 币种、`report_date` 时区时，匹配只作为预览，不写正式周报。广告活动名称、广告成交归因销售额不参与归属。活动差异按活动隔离。
- `hsaProductAds`、`sdProductAds` 只读当前目录查询已接入并通过合成分页测试；SB `sbDivideAsinReports` 因用户提供的字段表与示例错位被安全阻止，不发送请求。缺少修正后的官方响应字段结构、`spends`/`percent` 逐项类型及语义、是否返回每个 SKU/ASIN 的实际分摊金额和如何与活动 cost 核平。SB 视频费用覆盖和历史推广身份有效期也未由现有 Schema 说明。普通 HTTPS 文档访问在 Codex 云端被代理拒绝（403）；上传的旧版 Java SDK 中未找到 SB/SD 报表实现。
- 六份广告报表接口文档列出的令牌桶容量为 10，但没有说明补充速率或跨接口共享方式；遇到 429 时停止，不自动重试或猜测限速间隔。多日报表分页需在 Windows 授权环境验证实际限流表现。
- 自动化测试使用合成数据；本次变更后的实际通过数以最终测试输出为准。云端测试、模拟响应和 SDK 静态分析均不代表真实业务验收。

## 当前进度（2026-10-16）

- **P0 代码已实现，待 Windows 本机端到端验收：** 手动 D01 编辑、显式确认、本机按 SID/SKU 持久化、缺少 D01 时阻止生成；已有周报改 D01 时警告并确认日期错位。OpenAPI 销售查询可独立写入原模板，缺失与明确零值分开，销售额/订单量写入校验日志，支持 D61+ 与人工字段保护。SB 未解决不会阻止销售周报生成。
- **P1 自动归属与预览持续开发：** 用户报告 SP 与部分日期 SD 历史商品花费已通过 Windows 对照。SD 使用历史商品报表的日期级 SKU/ASIN 标识归属，不以当前目录作为前置条件。SB 的 SKU 级及店铺级数值已由用户核对，但程序仍缺分摊响应结构/金额口径，保持 SB 未归属。
- 广告自动化回归覆盖冲突、活动核平、完整/部分覆盖等合成边界；不代表广告真实验收。用户已报告店铺列表、每日销售数据、SP 和指定日期 SD 真实验收通过；D01→Excel 完整 Windows 操作、SB 自动归属、更多 SD 日期、完整跨类型广告总额仍待验收。
- **剩余里程碑：** P0 Windows 确认点击“领星 OpenAPI 查询并生成”后工作簿内容、D61+、手动字段保护和日志；P1 获取 `sbDivideAsinReports` 修正版 Schema/SDK，继续扩展 SD 不同日期真实对照；未确认 SB 前继续生成销售 Excel，广告总花费留空。P3 Windows EXE、版本号/更新提示；P4 第二台无 Python 的 Windows 电脑独立安装验收。每项仍属于 V1.0。

## 模块边界与共同规则

1. GUI 只处理用户输入、进度、结果和诊断；不自行拼 API 参数或推断业务口径。
2. OpenAPI、MCP、Excel/CSV provider 输出统一的按店铺/SKU/站点日期记录。记录保留来源、统计口径、查询覆盖、完整性和归属信息；金额在业务层使用 `Decimal`。
3. 业务层验证重复、缺项、错误 SID、MSKU 跨 SKU 映射、日期不一致和共享广告实体。任何字段无法唯一归属时，相关值为空并写清原因。
4. 报表层仅将真实且字段口径匹配的数据写入相应模板列。当前模板没有日销售额或总订单量字段时，把这些已核验值写入本地数据校验日志，不改变模板字段含义。
5. 日目标销量、发货时间、推广阶段保持人工维护；缺失值绝不改写为 0。输出默认新文件；增量更新需保留已有手工内容。
6. 领星公司共用 API 凭证只在每位用户自己的 Windows Credential Manager 保存；不开发员工账号、云数据库、角色权限或独立员工凭证。
7. 公开仓库、诊断和版本包不得包含 AppID/AppSecret、Token、Seller ID、真实业务明细或未脱敏接口响应。

## 开发与交付节奏

每次变更聚焦一个可独立验证的功能：先合成数据单测和接口模拟，再在 Windows 本机真实授权环境核对，更新验收状态后提交 `feature/weekly-report-v1`。无真实验收时明确标记“待 Windows 验收”。任何官方参数、日期范围、退款口径、限流策略或广告归属缺少证据时，先阻止相关数据写入并记录所缺文档，不猜测实现。

### P0 的本机验收步骤

1. 在 Windows 更新 `feature/weekly-report-v1`，启动 GUI，刷新店铺并选择实际返回的目标店铺。
2. 输入测试 SKU 与运营人员确认的 `YYYY-MM-DD` 日期，点击“确认并保存 D01”；关闭并重启程序后确认同一店铺/SKU 自动载入日期。另一个 SID 下应为独立设置。
3. 先尝试缺少 D01 的 SKU，确认生成被拒绝；再用确认的 D01 查询 ex3106，检查销售日期、日销、单价及日志中的销售额/订单量。
4. 检查 D01、连续日期、D61+、周次、模板样式、缺失/零值、人工字段。超过接口上限时验证窗口边界无重复/漏日；任何 429、业务码错误、映射不唯一或部分窗口失败时，不输出看似完整的周报。
5. 更新现有周报时先确认 D01 未变；再更改 D01，检查保存时风险提示和生成时再次确认。另存新文件，核对原始工作簿与日目标销量、发货时间、推广阶段等人工值。

### P1 的 Windows 本机验收步骤

1. 更新 Windows 分支，刷新店铺，选择授权店铺，输入用户指定的测试 SKU 和站点日期范围，点击广告费用预览。
2. 比较 SB 当前创意目录 ASIN、广告组/活动 ID 与领星后台，并核对用户指定 SKU 的 SB 专属花费。当前目录不含历史快照，预览应显示候选 ID 并将 SB 历史费用留为未归属；再按日核对 SP/SD 商品 cost 与对应活动 cost。
3. 检查页面按日期、类型显示本地 SKU、MSKU、ASIN、Ad ID、Profile ID、Campaign ID、Ad Group ID 和状态。活动值仅用于核对、不重复相加；未归属、冲突、不核平记录独立提示。币种、日期口径未确认前跨类型合计空白，预览不写入 Excel。
4. 分别反馈本地参数校验、各 API 请求及业务码成功/失败、是否返回真实记录、活动/明细成本是否逐日一致。仅需脱敏状态和字段结构，不要发送 AppID、AppSecret、Token、SID、订单/商品明细或原始响应。

### 进入下一阶段所需的资料和决策

- D01 无待补充订单接口要求：用户明确选择手动 D01，不继续开发通过历史订单搜索自动确定 D01。
- SB 自动归属缺少 `sbDivideAsinReports` 修正官方 Schema/SDK 输出：明确 `data` 记录类型、`spends`/`percent` 嵌套结构及是否为 SKU/ASIN 级实际花费、合计如何与活动/广告组成本核平、历史覆盖/结算范围、视频覆盖、币种及时区。若此接口不返回 SKU 级实际花费，需要领星提供另一个官方 SB 商品级 spend 或按报表日历史推广商品接口。当前 `hsaProductAds` 目录不能回溯 2026-08-29 的推广身份。
- SD Windows 实测仍缺精确报表状态：`sdProductAds` 当前目录 39 条不含日期和 cost；历史 `sdProductAdReports` 无明细。需要确认各目标日期的 HTTP/业务 code、`total`、对应 `sdCampaignReports` 行数，并取得官方历史数据范围/延迟说明或提供有效的商品级费用接口。当前预览会区分“历史商品无记录”与明确零值。
- 若要考虑广告费用正式进入周报，需先完成用户指定店铺和 SKU 的三类型逐日后台对照；必须确认广告关闭后花费、活动/明细 cost 一致性、币种及日期语义。当前只预览，不写入。
- 正式更新检查：管理员选定可信 HTTPS 版本清单/发布地址。不得自行部署或发布公司稳定版。
