# 新品推广周报 V1.0 实施清单与验收标准

本计划涵盖 V1.0 正式交付范围。当前开发分支为 `feature/weekly-report-v1`，稳定版 `main` 不在本阶段直接修改。业务范围仅限新品推广周报；广告管理、调价、库存管理、利润分析及企业云平台不属于 V1.0。

## 产品路线与当前验收基线

- **领星 OpenAPI** 是主数据来源；官方 MCP 保留为辅助查询和核验渠道；领星 Excel/CSV 是接口不可用时的备用来源。
- 已有模板生成器支持原模板格式、连续日期、D61+、校验 JSONL、多个 SKU 和增量更新时保留人工字段。
- Windows 本地真实验收：动态店铺列表已通过；用户报告 SKU 映射、每日销量、订单量、销售额查询在 EX-shop-US / ex3106 与领星后台一致。此记录是用户提供的验收结果，Codex 云端没有访问凭证或原始数据。
- 已实现的销售 API 文档范围：产品表现 `POST /bd/productPerformance/openApi/asinList`、每日统计 `POST /erp/sc/data/sales_report/asinDailyLists`。产品表现日期窗口上限 92 天；每日统计按站点自然日查询，按 ASIN/MSKU 和指标类型分页。
- **D01 规则已由用户最终确认：手动输入并确认。** 每个店铺/SKU 独立设置 `YYYY-MM-DD`，按该店铺站点日期解释；本机持久化，后续更新复用。不能从商品创建日期、订单、首个有销量日期或其他来源自动替代。修改已有工作簿起算日之前必须警告日期错位并重新确认。订单列表不再是 V1.0 的 D01 依赖。
- 用户已提供的 AsinDailyLists 文档未说明按日期查询的令牌桶补充速率；收到 429 必须停止，不猜测等待时间、不自动重放。多日历史查询的限流行为需在 Windows 授权环境实测。
- 用户报告 EX-shop-US / ex3078 的 SP 广告实际花费已在 Windows 与领星后台核对一致；此真实验收结果来自用户反馈，云端没有凭证或原始业务响应。
- 已收到 SP Campaign/Product Ad、SB Campaign/Ad Group、SD Campaign/Product Ad 的官方 Schema。当前只读查询按 SID、profile、campaign 和站点报表日期核活动成本与商品/广告组成本；活动级 cost 仅作核对，不与明细重复相加。
- **广告归属方向已调整为自动匹配优先。** 新增 `ad_attribution.py`：SP/SD 行按唯一 MSKU/ASIN 自动映射；SB 独占广告组路径只有在推广商品目录完整、组内所有身份唯一映射到同一本地 SKU、活动与广告组金额核平后才归属。官方已分摊的 SB SKU/ASIN 金额也有受控输入口，但适配器必须先核实 `spends`/`percent` 的官方语义。现有 GUI 详情行增加 ASIN、Ad ID。
- 当前 `productPerformance` 映射没有逐日 MSKU/ASIN 有效期；缺少历史身份时效证据、广告 cost 币种、`report_date` 时区时，匹配只作为预览，不写正式周报。广告活动名称、广告成交归因销售额不参与归属。活动差异按活动隔离。
- 新增接口 `/pb/openapi/newad/hsaProductAds`、`/pb/openapi/newad/sbDivideAsinReports`、`/pb/openapi/newad/sdProductAds` 尚未接入。Codex 云端通过公开文档域名请求收到代理 HTTP 403；不能由路径猜参数或响应字段。SB 视频覆盖、完整商品目录声明、ASIN/SKU 与广告 ID 的关系、分摊金额/百分比口径仍待用户提供这三份完整 Markdown Schema。
- 六份广告报表接口文档列出的令牌桶容量为 10，但没有说明补充速率或跨接口共享方式；遇到 429 时停止，不自动重试或猜测限速间隔。多日报表分页需在 Windows 授权环境验证实际限流表现。
- 当前自动化测试仅使用合成数据。云端测试、模拟响应和 SDK 静态分析均不代表真实业务验收。

## 模块边界与共同规则

1. GUI 只处理用户输入、进度、结果和诊断；不自行拼 API 参数或推断业务口径。
2. OpenAPI、MCP、Excel/CSV provider 输出统一的按店铺/SKU/站点日期记录。记录保留来源、统计口径、查询覆盖、完整性和归属信息；金额在业务层使用 `Decimal`。
3. 业务层验证重复、缺项、错误 SID、MSKU 跨 SKU 映射、日期不一致和共享广告实体。任何字段无法唯一归属时，相关值为空并写清原因。
4. 报表层仅将真实且字段口径匹配的数据写入相应模板列。当前模板没有日销售额或总订单量字段时，把这些已核验值写入本地数据校验日志，不改变模板字段含义。
5. 日目标销量、发货时间、推广阶段保持人工维护；缺失值绝不改写为 0。输出默认新文件；增量更新需保留已有手工内容。
6. 领星公司共用 API 凭证只在每位用户自己的 Windows Credential Manager 保存；不开发员工账号、云数据库、角色权限或独立员工凭证。
7. 公开仓库、诊断和版本包不得包含 AppID/AppSecret、Token、Seller ID、真实业务明细或未脱敏接口响应。

## 开发与交付节奏

每次变更聚焦一个可独立验证的功能：先合成数据单测和接口模拟，再在 Windows 本机真实授权环境核对，更新验收状态后提交 `feature/weekly-report-v1`。无真实验收时明确标记“待 Windows 验收”。任何官方参数、日期范围、退款口径、限流策略或广告归属缺少证据时，先阻止相关数据写入并记录所缺文档，不猜测实现。

### P0 的本机验收步骤

1. 在 Windows 更新 `feature/weekly-report-v1`，启动 GUI，刷新店铺并选择实际返回的目标店铺。
2. 输入测试 SKU 与运营人员确认的 `YYYY-MM-DD` 日期，点击“确认并保存 D01”；关闭并重启程序后确认同一店铺/SKU 自动载入日期。另一个 SID 下应为独立设置。
3. 先尝试缺少 D01 的 SKU，确认生成被拒绝；再用确认的 D01 查询 ex3106，检查销售日期、日销、单价及日志中的销售额/订单量。
4. 检查 D01、连续日期、D61+、周次、模板样式、缺失/零值、人工字段。超过接口上限时验证窗口边界无重复/漏日；任何 429、业务码错误、映射不唯一或部分窗口失败时，不输出看似完整的周报。
5. 更新现有周报时先确认 D01 未变；再更改 D01，检查保存时风险提示和生成时再次确认。另存新文件，核对原始工作簿与日目标销量、发货时间、推广阶段等人工值。

### P1 的 Windows 本机验收步骤

1. 先接入三份待补官方 Schema 后，更新 Windows 分支，刷新店铺并选择 EX-shop-US，输入 `ex3114`，设定 `2026-08-29` 至 `2026-08-29`，点击广告费用预览。
2. 比较 SB 商品推广标识、广告组/活动 ID 与领星后台。核对 SB 专属实际花费 `$19.21`；若归属引擎仍提示未归属，记录缺失的关系字段或完整目录证据。再按日核对 SP/SD 商品 cost 与对应活动 cost。
3. 检查页面按日期、类型显示本地 SKU、MSKU、ASIN、Ad ID、Profile ID、Campaign ID、Ad Group ID 和状态。活动值仅用于核对、不重复相加；未归属、冲突、不核平记录独立提示。币种、日期口径未确认前跨类型合计空白，预览不写入 Excel。
4. 分别反馈本地参数校验、各 API 请求及业务码成功/失败、是否返回真实记录、活动/明细成本是否逐日一致。仅需脱敏状态和字段结构，不要发送 AppID、AppSecret、Token、SID、订单/商品明细或原始响应。

### 进入下一阶段所需的资料和决策

- D01 无待补充订单接口要求：用户明确选择手动 D01，不继续开发通过历史订单搜索自动确定 D01。
- 广告后续需要 Windows 实测确认：各类型 `report_date` 口径、cost 币种、SP/SD 商品行 `sku` 与本地 MSKU 对应关系、SB 视频覆盖范围。SB/SD 的基础请求/响应 Schema 已足够实现只读预览；若官方另有广告类型/视频 campaign 覆盖说明，请补充该说明，不需要再次提供已给出的基础 Schema。
- 若要考虑广告费用正式进入周报，需先完成 EX-shop-US/ex3078 在 2026-08-28 至 08-29 的三类型逐日后台对照；必须确认广告关闭后花费、活动/明细 cost 一致性、币种及日期语义。当前只预览，不写入。
- 正式更新检查：管理员选定可信 HTTPS 版本清单/发布地址。不得自行部署或发布公司稳定版。
